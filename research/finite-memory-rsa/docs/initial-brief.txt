# 一、研究背景和核心动机

我们希望研究 Random Sequential Adsorption（RSA，随机顺序吸附）中一个非常受限但此前似乎缺乏系统研究的问题：

**如果吸附系统完全看不到基底的空间状态，只能得到自己过去吸附尝试成功或失败的信息，那么极少量内部记忆究竟能提供多少控制能力？**

标准 RSA 中，吸附尝试通常可以看作彼此无记忆或由预设分布决定。已有研究已经大量涉及：

- 不同粒子形状；
- k-mer；
- 不同晶格；
- 各向异性或固定取向偏置；
- cooperative / correlated adsorption；
- 粒子与局部已吸附结构之间的相互作用；
- relaxation / rearrangement；
- percolation 与 jamming；
- 部分取向、局部 polarization 等。

但我们关心的是另一种非常具体的反馈：

**新的粒子不观察空间结构，也不知道覆盖率、空位、邻域、当前位置等信息，只知道以前的尝试是否成功。系统内部只有极有限的 finite-state memory。**

初步文献检索没有发现对如下精确定义进行系统穷举和定量研究的工作：

**success/failure-only temporal feedback + finite-state internal memory + exhaustive controller-space analysis in RSA**

不要轻率宣称“世界上从来没人做过”。在正式形成论文结论前，应继续检索最接近的关键词和模型，并明确区分本项目与已有工作的差别。可以重点检索：

- random sequential adsorption memory
- finite-state RSA
- history-dependent adsorption
- feedback-controlled adsorption
- adaptive random sequential adsorption
- correlated sequential adsorption
- cooperative adsorption
- partially oriented k-mer RSA
- finite-memory stochastic packing
- feedback jamming
- internal-state adsorption
- temporal correlations in RSA

如果能够联网，应主动查阅相关论文和综述，记录真正最接近的工作、模型差异、年份和引用信息。建立 `literature/notes.md`，而不是把文献搜索当成一句话带过。

# 二、基础模型

从二维方格晶格开始。

设格子大小为：

L × L

粒子最初考虑长度为 k 的 straight k-mer，只允许两个方向：

H = horizontal  
V = vertical

采用不可逆吸附：

- 每一次尝试选择一个候选位置；
- 如果对应的 k 个格子全部为空，则成功吸附；
- 否则失败；
- 成功吸附的粒子以后不能移动或删除。

边界条件应至少研究 periodic boundary 和 open boundary 中一种；如果边界效应可能重要，应比较两者。

核心创新不是位置选择策略。

为了避免控制器偷偷通过位置感知获得额外信息，基础版本中粒子的候选位置应保持均匀随机。

控制器唯一能够影响的是：

**orientation choice，以及内部有限状态。**

系统向控制器反馈：

y_t ∈ {success, failure}

控制器拥有内部状态：

q_t

在最基础的 1-bit 模型中：

q_t ∈ {0,1}

orientation function：

o_t = g(q_t)

其中：

o_t ∈ {H,V}

尝试以后：

q_(t+1) = f(q_t, y_t)

控制器不能看到：

- lattice configuration
- occupancy map
- local neighborhood
- current coverage
- number of available placements
- attempted coordinate
- cluster information
- global orientation order
- absolute time step

除非在后续扩展实验中明确放宽信息结构。

# 三、第一核心问题：完整研究所有 deterministic 1-bit controllers

对于 1-bit memory：

方向函数：

g : {0,1} → {H,V}

共有：

2² = 4

种。

状态转移：

f : {0,1} × {success,failure} → {0,1}

一共有四种输入，每个输出为 0 或 1，因此：

2⁴ = 16

种。

所以确定性 1-bit controller 总数：

4 × 16 = 64

这是项目最重要的优点之一。

不要只挑几个“看起来有趣”的策略。

应：

**完整枚举全部 64 个 deterministic one-bit controllers。**

然后研究这些 controller 是否可以按照行为或数学结构分类。

尤其寻找对称性，例如：

- state 0 ↔ state 1 relabeling；
- H ↔ V exchange；
- initial state equivalence；
- unreachable internal states；
- controllers equivalent under transformation；
- degenerate controllers；
- periodic state dynamics；
- failure-triggered switching；
- success-triggered switching；
- alternating / persistent / absorbing behavior。

如果可以，将 64 个 controller 化成少量等价类，并给出严格或至少程序验证过的等价关系。

不要因为总数小就只输出一个 64 行表格。目标是理解整个 controller space 的结构。

# 四、不要把研究目标简单定义成“谁 packing density 最高”

这是一个重要陷阱。

如果只追求最大 jamming coverage，一个永远选择 H 或永远选择 V 的策略可能因为完全 alignment 而获得很好的 packing，而这并没有证明“记忆”提供了智能优势。

因此必须同时研究宏观方向序。

定义至少一个 orientation order parameter，例如：

S = (N_H - N_V) / (N_H + N_V)

或者一个对 H/V 对称、更适合统计物理的等价定义。

重点分析：

- jamming coverage θ_j
- |S|
- adsorption efficiency
- failure rate
- temporal orientation correlations
- hole structure
- domain structure

一个非常重要的问题是：

**在保持宏观各向同性（例如 |S| 接近 0）的约束下，一位记忆是否仍然能够改变甚至提高 jamming performance？**

考虑构造：

packing performance vs orientational order

的 Pareto frontier。

不要强迫结果必须“提高 packing”。

如果发现：

- 1-bit feedback 无法在 isotropy constraint 下产生任何优势；
- 所有优势都可以解释为 orientation bias；
- 存在理论上明显的上界；

这些本身也是有价值的负结果，只要论证充分。

# 五、严格区分 geometric jamming 与 controller-induced deadlock

这是值得重点发展的概念。

可能出现这样的状态：

当前 controller 接下来不会再生成某个方向，或者内部状态进入某种循环，因此实际运行中永远无法成功吸附；

但如果允许另一个方向，晶格上事实上仍存在合法 placement。

因此至少区分：

### Geometric jamming

对于允许的粒子方向集合而言，整个 lattice 已经不存在任何合法 placement。

### Controller-induced deadlock

仍然存在合法 placement，但 controller 的有限状态动态使这些 placement 永远无法被尝试到。

需要给出严格定义。

程序不要仅仅通过：

“连续失败 100000 次，所以认为 jammed”

来判断最终状态。

应考虑维护或高效判断合法 placement 的存在性，从而能够真正区分：

- stochastic long waiting
- policy deadlock
- true geometric jamming

如果需要，可以设计 event-driven 或合法位置数据结构来提高效率。

这个区分可能成为论文的重要贡献之一。

# 八、从 1 bit 扩展到 2 bit

1-bit 研究完成以后，再考虑：

q_t ∈ {0,1,2,3}

即 2-bit / four-state controller。

方向输出：

g : 4 states → {H,V}

共有：

2⁴ = 16

个 orientation functions。

状态转移：

f : 4 states × 2 outcomes → 4 states

共有 8 个输入，每个选择四个下一状态：

4⁸ = 65,536

因此 controller 总数：

16 × 65,536
= 1,048,576

这已经足够形成真正的大规模 finite-state strategy landscape。

不要天真地对 1,048,576 个策略全部直接使用最大 L 和最大 Monte Carlo repetitions。

应设计高效搜索流程，例如：

1. 去掉显然等价或不可达状态；
2. 小 L 快速筛选；
3. 少量 seed 初筛；
4. 找 Pareto candidate；
5. 对候选 controller 进行高精度模拟；
6. 必要时使用 adaptive racing / successive halving；
7. 分析 controller behavior classes，而不是只找 top controller。

如果能找到对 controller graph 的理论分类或 canonical representation，会比暴力筛选更有价值。

允许进一步考虑“最少需要多少 memory 才能产生某类宏观结构”。

# 九、精确小系统计算

这是一个重要的加强方向。

Monte Carlo 不应该是唯一方法。

对于足够小的：

L
k

尝试完整表示系统状态：

(lattice configuration, controller state)

将其视作有限 Markov process / absorbing stochastic process。

如果计算规模允许：

- 枚举所有 reachable states；
- 构造 transition graph；
- 识别 absorbing states；
- 精确计算 absorption probabilities；
- 精确计算 expected terminal coverage；
- 精确计算 deadlock probability；
- 比较不同 controllers。

可使用 rational arithmetic 或高精度 floating point 进行小规模验证。

至少选择几个小系统，与 Monte Carlo 结果进行交叉验证。

如果状态空间过大，应研究：

- symmetry reduction
- bitboard representation
- dynamic programming
- sparse transition representation
- canonical states

这部分可以形成一个很强的理论/计算支撑。

# 十、finite-size scaling

不要只在一个 L 上跑然后下宏观结论。

至少考虑多个系统大小，例如：

L = 16, 32, 64, 128, 256, 512

具体范围根据性能决定。

分析：

θ_j(L)

以及其他关键 observable 如何随 L 变化。

如果合理，尝试外推：

L → ∞

并给：

- confidence intervals
- finite-size corrections
- scaling fits
- bootstrap / jackknife 或合适的误差估计

不要为了得到漂亮曲线而过度拟合。

如果不存在可信的 scaling law，就诚实报告。

# 十一、随机 controller

确定性策略只是起点。

如果有意义，可以允许：

P(H | q)

和：

P(q' | q,y)

是概率分布。

研究 stochastic finite-state controllers 是否能够实现 deterministic controller 做不到的 performance / isotropy trade-off。

不要一开始就把参数空间无限连续化。

优先从：

- 少量离散概率；
- deterministic controller 附近扰动；
- symmetry-constrained stochastic controller

开始。

如果发现随机化没有额外价值，也可以把这一点作为结果。

# 十二、feedback noise 和 delay

这是后期扩展，不要在基础模型尚未理解以前过早加入。

Noise：

控制器以概率 ε 错误读取 success/failure。

Delay：

控制器看到的是：

y_(t-d)

而不是当前结果。

可以研究：

- controller robustness
- critical noise level
- graceful degradation
- strategy ranking stability
- delayed feedback induced oscillations

尤其关注：

**某些高性能 controller 是否实际上极其脆弱？**

如果存在“稍微错误的反馈反而提高性能”的 stochastic-resonance-like 现象，应认真验证而不是直接当成 bug。

# 二十一、研究失败标准与成功标准

不要把“找到一个 packing 更高的 controller”定义成唯一成功。

以下任何一种都可能构成有价值结果：

### A
发现有限记忆在 isotropic constraint 下确实提高 jamming coverage。

### B
证明所有观察到的优势都来自简单 orientation bias，memory 本身无额外收益。

### C
发现新的 controller-induced deadlock phenomenon。

### D
发现 controller memory 引入新的结构或动力学 regime。

### E
得到清晰的 memory-information-performance trade-off。

### F
得到 finite-state controller 的数学分类。

### G
找到非平凡的 1-bit / 2-bit strategy classes。

### H
发现 noise/delay 导致意外现象。

### I
得到有意义的 negative result 和理论解释。

真正失败只有一种：

**跑了大量 simulation，却没有把任何现象变成清晰、可验证的科学问题。**

避免这种情况。

# 二十二、执行方式

请不要只回复我一份计划。

你拥有电脑执行能力，所以要真正开展研究。

按下面的方式行动：

1. 检查当前工作目录和可用环境。
2. 建立项目结构和研究日志。
3. 做针对性的文献检索。
4. 写下 formal model。
5. 实现最小正确 simulator。
6. 做测试和 sanity checks。
7. 枚举全部 64 个 1-bit controller。
8. 运行第一轮小规模探索。
9. 分析结果。
10. 根据数据决定下一步，而不是机械执行所有预想实验。
11. 优化值得深入的部分。
12. 增加 exact / finite-size / information-theoretic 分析。
13. 如果值得，再进入 2-bit controller。
14. 不断更新研究日志。
15. 最终形成完整、可复现的结果。

研究过程中，如果一个结果足以改变后续研究路线，应根据结果调整，不要受原始计划束缚。

# 二十五、最终科研标准

请用这样的标准要求自己：

不是：

“我成功模拟了一个有趣的 cellular system。”

而是：

**“我提出并系统研究了一个定义清楚的有限信息随机控制问题，并且能够用完整的计算证据、统计分析和必要的理论推理说明系统到底发生了什么。”**

结果应该经得起下面这些质疑：

- 这只是随机波动吗？
- 这只是 orientation bias 吗？
- 这只是 finite-size artifact 吗？
- 这只是一个 controller 的巧合吗？
- 换 seed 还成立吗？
- baseline 是否公平？
- 真的是 memory 的作用吗？
- 是否存在等价的 memoryless policy？
- 所谓 jamming 是否其实只是没等够？
- 是否只是 implementation bug？
- 有没有已经有人研究过？
- 现象能不能被更简单的解释说明？

请主动攻击自己的结论，而不是替自己的结论辩护。

**先理解问题，再做实验；先让数据说话，再决定研究重点。**

如果你发现比这里预设的方向更漂亮、更严谨、更值得发表的东西，请大胆沿着那个方向走。

但无论最终方向如何变化，都要保持模型简单、问题明确、证据充分、代码可复现，并争取从这个极小的“1 bit memory”设定中挖出一个真正值得讲的科学故事。
