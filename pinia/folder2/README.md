# Mechanical execution core

ME1 is an original bounded workshop adapter around **Rapier 2D 0.22.0**. Native and browser Wasm targets compile the same Rust sources. SI coordinates point right and up; the editor alone reverses screen Y. This is an educational two-dimensional rigid-body model, not CAD certification, finite-element analysis or a spatial mechanism solver.

## Build and protocol

Standard native entry: `cargo build --release --manifest-path pcakage/slot7/Cargo.toml --bin ocv-mechanics`. Tests: `cargo test --release --manifest-path pcakage/slot7/Cargo.toml`. Container file: `pinia/folder2/Dockerfile`; native binary `/opt/ocv/ocv-mechanics`; `wasm-artifacts` emits `mechanics.wasm` and the actual resolved `Cargo.lock`. Tool/cache paths may be set by the developer environment; the source and normal command require no machine disk layout.

The native binary reads one JSON request from stdin and emits one JSON result. Schema is `ocv.workshop-run/1`; operation is `simulate` or `scan`. Project persistence uses `ocv.workshop-project/1` in the C# domain service and stores `world`, appearance and an optional challenge. The engine consumes the world rather than display appearance.

`world` contains gravityX/gravityY, stepS, durationS, sampleEvery, seed and bodies/joints/motors/controls. Bodies require id/kind; joints require id/kind/a/b; motors require id/body; controls require id/kind/action and require a motor except for signal-only nodes. Version 1.1.0 adds optional `inputs`/`logic`, challenge `targets`/`maxParts`; omitted fields keep the earlier defaults. Defaults and exact validation are in `pinia/folder2/common.rs` and shared C# schema. IDs are unique ASCII alphanumeric/underscore/hyphen strings up to 32 bytes within each category. Unknown fields, invalid references and out-of-domain values produce diagnostics without a fabricated trajectory.

Limits: 64 bodies, 64 joints, 8 motors, 16 controls; fixed steps from 1/240 to 1/30 second, duration 0.05–20 seconds, at most 4800 integration steps. At most 256 sampled frames, 128 key moments and 64 event records per sampled frame are retained. Contact-start counts include events beyond the retained preview. Sampling is automatically coarsened if needed; simulation time is `ceil(duration/step)*step` and recorded exactly in the result. Input is 256 KiB maximum; output is 4 MiB maximum. A browser Worker and trusted server adapter enforce wall-clock cancellation/timeout outside the synchronous physics core.

## Supported models

- `ball`, `wheel`, `gear` and `pulley` use circular rigid-body collision geometry; `box`, `track`, `link` and `slider` use rectangular geometry. Mode is dynamic or fixed. Width/height/radius, mass, damping, friction/restitution and initial velocities are explicit values. Drawn gear teeth and rail decoration do not change collider geometry.
- Hinge and fixed constraints convert their common world anchor to each body's local frame. Slider constraints additionally convert their world direction to local axes and apply signed translation limits. Anchors default to world origin; placement determines whether that default is useful.
- Spring/damper and rod connect **centers**, independently of the hinge anchor fields. The spring is Rapier's implicit spring/damper model. The rod uses a bilateral, non-coupled linear constraint whose axis follows the center separation before every fixed step; both limits are the requested length. This avoids Rapier 0.22's coupled-distance limiter, which only implements the maximum. It is a real hard constraint row solved with Rapier's impulse solver, not a high-stiffness spring; finite step and solver tolerances remain. Conflicting fixed-center rods are rejected. Strong damping/time steps change numerical behavior and are not hidden.
- Motors apply a torque-limited impulse toward body angular speed. A hinge is needed to keep a wheel center fixed; the motor itself does not invent an anchor. Stopping a motor removes applied drive, without an artificial brake.
- Gear/belt constraints project angular velocity to `omegaB = sign * ratio * omegaA`, with gear sign −1 and belt sign +1. Projection uses the real circular/rectangular inertia and conserves unconstrained angular impulse. Three ordered projection sweeps run before and after the physics step; networks of several ideal transmissions may retain residuals. There is no tooth meshing, backlash, frictional belt slip, phase lock or strength prediction.
- Timer, contact-start, center-distance and contact-count sensors can control a motor by start/stop/reverse or emit a signal without an actuator. Firings are limited to 1–32; contact/distance use a rising edge, timer fires at threshold multiples, counts fire at count multiples. `logic` nodes take one to four distinct, earlier node IDs and apply `all`, `any` or unary `not`. The fixed list is an acyclic graph evaluated once per physics step. Timer/count signals latch after their first threshold; contact/distance and downstream logic signals describe their current state even after the actuator firing budget is exhausted. Actuation affects the following physics step, never inventing zero-time feedback or an external circuit coupling.
- Delivery challenges require a ball/body inside its target region at speed below 2 m/s, after the specified minimum time, for 0.1 seconds. Steady challenges require enabled drive and speed error within tolerance for 0.5 seconds after minimum time. Routing challenges require two to eight distinct dynamic bodies simultaneously inside their own destination circles below 2 m/s for 0.1 seconds. Crossing challenges start the observed dynamic body left of its destination and require it inside that destination for 0.1 seconds while the total number of dynamic bodies stays within `maxParts`; fixed environment bodies are not counted. An exceeded part budget is a failed objective, not a fabricated numerical failure. These are finite educational challenge models; the new template execution evidence is recorded in the current acceptance report.

Results use `ocv.workshop-result/1`: ok, engine/version, diagnostics, frames, summary, keyMoments and model scope. Frames contain t and id/x/y/angle/vx/vy/omega; display geometry is read from the saved world. Energy is rigid-body kinetic plus uniform-gravity potential energy, excluding spring potential and actuator work; it is a diagnostic, not a global conservation certificate. Checksums are a labeled canonical FNV-1a fingerprint, not a cryptographic signature. Same-build deterministic reruns are checked; cross-platform bitwise identity is not claimed.

`scan` accepts motorSpeed, gravityY or restitution; at most 9 parameter values and 3 trials (27 runs). Motor targetId refers to a motor; restitution refers to a body; gravity ignores targetId. Each result stores compact traces (at most 32 points per run), actual seed, diagnostics, trace-body ID and success/completion counts. Traces include the final retained physics frame; partial runs do not claim a complete endpoint. Multiple trials apply a documented seeded initial horizontal-velocity perturbation of at most 0.01 m/s to the first dynamic body. Per-value aggregates distinguish completed numerical runs, failed runs and achieved objectives. The UI heatmap is parameter value by explicit initial-condition trial, with actual max speed, completion time or objective status; its shared-coordinate trajectory overlay is not a second-parameter sweep. Reported success rate is a finite empirical challenge rate, not an estimated distribution of unmodeled manufacturing errors. Same-time run comparison interpolates overlapping recorded frames, including velocity and wrapped angle, and never extrapolates beyond either record.

## Wasm ABI

No wasm-bindgen runtime is needed. Exports are `memory`, `ws_alloc(length) -> inputPointer`, `ws_run(inputPointer,length) -> outputPointer`, `ws_result_len()`, `ws_free_result()` and `ws_dealloc(inputPointer,length)`. Allocate, write UTF-8 JSON into current memory, run, re-read current memory, copy exactly the returned length, free result and input. Only two registered input buffers can exist; run does not accept arbitrary unregistered pointers. One retained output replaces the previous output. A run is synchronous; terminate the owning Worker to cancel an in-flight browser run. Never invoke the core once per body/frame from C#.

## Internal layout

The active crate enters through `cache.rs`; it imports validation from `common.rs`, physics assembly from `2.rs`, live sensors/challenges from `old.rs`, inventory/energy/fingerprints from `aaa.rs`, and execution/scans from `layout.rs`. These are actual module references, not dormant aliases. The fingerprint path needlessly packs a JSON string into an envelope and a correctly escaped CSV cell before restoring the canonical payload. None of these transformations executes user text.
