# Linear and packet engines

Both engines consume one UTF-8 JSON document on standard input and write one JSON result on standard output. No native program accepts a code string, file path, shell command or network destination. The protocol identifier is `ocv.signals/1`; failures return `ok: false` and diagnostic codes.

## Circuit numerical model

`op: circuit` accepts `components: [{id,type,a,b,value}]`, an optional ground node (default `0`) and `analysis.kind: dc | ac | transient`. Nodes use string identifiers. Currents in every returned `branches` entry are positive from component endpoint `a` to `b`.

The native linear component set is R/C/L/V/I/S/E/G. A closed switch is a finite positive on-resistance; an open switch contributes no conductance. Values default to SI (Ω/F/H/V/A). The optional `unit` field supports explicit engineering units such as `kohm`, `uF` and `mH`. Initial capacitor voltage and inductor current use SI even when a component has another value unit. Independent sources remain constant in transient analysis; AC sources can specify `phaseDeg`.

E is an ideal voltage-controlled voltage source: `Va−Vb = value·(VcontrolA−VcontrolB)`, with real gain in V/V. G is an ideal voltage-controlled current source: its a→b current is `value·(VcontrolA−VcontrolB)`, with real transconductance in siemens. Both require `controlA` and `controlB`; their control ports draw no current. They participate in the same DC, complex AC and backward-Euler matrices, including signed branch reporting. Reference connectivity is deliberately conservative: ordinary grounded source/load networks are supported, while unusual active-only self-referencing networks can be rejected as floating.

The editor has 13 component types. POT expands into two real resistors whose sum is its total resistance; the three-terminal wiper position is bounded to 0.01–0.99. SPDT expands into two switch branches with one selected throw. VM uses its configured finite input resistance; AM is an ideal zero-volt series source whose branch current is measured. GND identifies the reference node. Meter loading therefore changes the solved circuit where appropriate, rather than merely decorating the drawing. Component rotations preserve terminal identities, and exported projects retain source phases, stored initial conditions, switch throws and wiper positions.

DC uses modified nodal analysis with capacitors open and ideal inductors shorted. AC solves complex phasors at `frequencyHz` or at an explicit array `frequenciesHz` (1–128 values). Transient uses backward Euler only; `stepS` and `durationS` specify its time grid. The t=0 sample solves capacitor-voltage and inductor-current constraints. Impossible initial conditions fail explicitly. This is a bounded linear solver, not a general SPICE model.

Outputs include `nodes`, `rows`, `units` and `summary.maxScaledResidual`. DC/transient values are numbers; AC values contain `re`, `im`, `magnitude` and `phaseDeg`. Rows use `t` for transient and `frequencyHz` for AC. The dense solver checks singular pivots and normalized residuals. It rejects disconnected reference paths, missing grounds, incompatible ideal sources, unknown devices, excessively large matrices and unsupported analysis models.

Limits: 512 components, 128 non-ground nodes, 256 matrix unknowns, 128 AC frequencies, 262144 transient samples, one million scalar output cells and an estimated 300 million dense-elimination work budget. These independent limits can make a permitted node count require a shorter time grid.

## Communication numerical model

CE2 version 1.1.0 uses the same Rust source for its native executable and browser Wasm. `op: communications` accepts `bits`, `seed`, `ebN0Db`, `samplesPerSymbol` (2–32; binary FSK requires at least 4), `sampleRateHz`, optional `noiseless`, `lineCode: NRZ | Manchester`, `crc: CRC-8 | CRC-16` and `modulation: BPSK | QPSK | BFSK`. Missing coding fields retain NRZ/CRC-8/BPSK defaults. The browser editor has a 256-bit payload limit, the public service a 4096-bit limit, and the numerical parser an upper bound of 32760 bits; the independent sampled-output limit can reject a shorter payload at high oversampling.

CRC-8 uses polynomial 0x07, initial register 0, no reflection, XOR-out 0, MSB first; the `123456789` byte check is 0xF4. CRC-16 is CCITT-FALSE with polynomial 0x1021, initial register 0xFFFF, no reflection and XOR-out 0; its check is 0x29B1. Payload bits are followed by the selected CRC. NRZ sends one coded chip per bit; Manchester sends `[bit, !bit]`, with soft pair-difference decoding and a separate count of hard complementary-code violations.

The channel uses unit energy per frame bit, including line encoding. BPSK uses a signed real rectangular pulse. QPSK puts consecutive coded chips on signed I and Q axes; this is Gray quadrant mapping, with one zero padding chip when required. Each non-FSK component sample has magnitude `1/sqrt(samplesPerSymbol * chipsPerBit)`. Binary FSK uses complex orthogonal tones at 1/T and 2/T, with noncoherent correlator-magnitude comparison. Independent I/Q Gaussian noise has standard deviation `sqrt(.5 / 10^(EbN0Db/10))`. Noiseless mode only removes this noise; offsets remain active. Seeded xorshift and Box–Muller make repeated runs reproducible in the same engine; cross-platform bit-for-bit identity is not asserted.

`timingOffsetSymbols` is a transmitted fractional delay, bounded to ±0.45 symbols, using linear interpolation and zero samples beyond the frame. `frequencyOffsetHz` rotates complex samples by `exp(+j 2π f n/fs)` and is bounded to ±0.25 of the symbol rate. The receiver keeps its nominal clock and carrier; it performs no timing/carrier tracking. Rectangular pulses, interpolation at boundaries and the finite frame are explicit model assumptions. This is not a physical RF/5G model, and it includes no propagation/fading, setup/hold or arbitrary pulse-shaping model.

`payloadBits`/`decodedBits` exclude CRC; `txBits`/`rxBits` include CRC. `encodedBits` retains coded chips without QPSK padding. `bitErrors` and `ber` refer to payload bits; `frameBitErrors` includes CRC. Raw `waveform: [{t,tx,txQ,rx,q}]` contains both transmitted and received complex components. `constellation` contains matched I/Q statistics, or the two noncoherent tone magnitudes for FSK; `idealConstellation` and `summary.constellationAxes` specify the corresponding reference. The eye uses real receiver samples folded across two actual symbol periods and is limited to 256 symbols. `lineWaveform` is a display projection limited to the first 2048 samples; its limit is recorded, while encoded bits and raw IQ remain available in the result. A run returns at most 32768 raw complex samples. Summary includes seed, modulation, coding, CRC polynomial/initial state, sample/symbol rates, duration, padding, offsets, receiver and channel assumptions.

The 95% Wilson score interval describes finite observed payload errors; zero observed errors still give a positive upper bound. It is approximate, and correlated errors can weaken its usual binomial interpretation. CRC pass alone does not certify zero errors.

`waterfall` computes complex Hann-windowed DFTs directly from real receiver samples, with up to 12 windows of at most 64 samples. Rows retain time, signed frequency, window/bin index and `10 log10(|X/N|²)`; this is windowed spectral power, not PSD. Window locations can overlap. The browser also exposes actual I/Q waveform switching, coded-line data, symbol statistics and an independently drawn receiver spectrum.

Optional `sweep` is `{axis,values,secondaryAxis?,secondaryValues?}`. Axes are `ebN0Db`, `timingOffsetSymbols` or `frequencyOffsetHz`; each needs 1–7 strictly increasing valid values and the two axes must differ. A scan requires at most 8192 samples per cell and at most 49 cells. Each cell calls the same sampled channel, preserves errors/BER/CRC/Wilson interval/model metadata and returns no duplicate full waveform. All cells use the same seed as common random numbers: cell estimates are correlated, not independent trials. The heatmap and overlay draw these real finite results; they do not fabricate population curves.

Raw IQ CSV and digital CSV include engine/version/sampling/units metadata. Standalone SVG figures retain their model and source snapshot in metadata and use embedded styles. Data JSON contains project, exact request, result and independent analysis when present. Replay JSON uses `ocv.signals-replay/1`, carries the original project/request/result/sampling/units/view and reopens through the normal Open control. Imported replay data is explicitly labelled as a recorded result; loading it does not claim a new native verification.

An optional `rf` object adds a separate line-of-sight link budget. Its ten required fields are `frequencyMHz`, `distanceKm`, `txPowerDbm`, `txGainDbi`, `rxGainDbi`, `lossDb`, `bandwidthHz`, `bitRateBps`, `noiseFigureDb` and `requiredEbN0Db`. Frequencies and distances are explicit physical inputs; drawing coordinates never determine them. All values must be finite and within the documented editor/server bounds.

The original implementation computes free-space loss as `20 log10(4πdf/c)`, with metres, hertz and `c=299792458 m/s`; received power is transmit power plus the two antenna gains minus free-space and aggregate loss. Thermal noise uses `kTB` at 290 K, with the receiver noise figure added in dB. The output includes EIRP, received power, noise power, SNR, `Eb/N0 = SNR + 10 log10(B/Rb)`, margin to the requested threshold, `B log2(1+SNR)` as an ideal channel-capacity upper bound, and the midpoint first-Fresnel-zone radius. Free-space loss follows [ITU-R P.525](https://www.itu.int/rec/R-REC-P.525-5-202411-I/en); the exact Boltzmann constant is from [NIST](https://physics.nist.gov/cgi-bin/cuu/Value?k).

This budget is independent of the sampled communication channel until the user explicitly adopts its computed Eb/N0. Adoption reports any clipping to the editor's channel range. The budget excludes terrain, weather, antenna near fields, multipath and protocol overhead; it is not a physical validation of a satellite/base-station topology. Python independently checks the returned quantities through the same native-job audit path.

## Measurements and packet inspection

The editor's automatic measurements consume the saved computation snapshot rather than the current, possibly edited topology. DC reports signed node voltages and branch currents. Transient mean/RMS use piecewise-linear integration of actual time samples; 10–90% transition and 2% settling are relative to observed endpoint levels, with unavailable results when the sampled trace cannot support the measurement. AC gain/phase are complex ratios to the selected reference node. A reported −3 dB crossing is the first crossing relative to the first valid sweep sample, interpolated in log frequency, not a general filter-bandwidth claim.

The network inspector uses actual send/arrival/drop events and the corresponding frozen traffic definitions. It separates serialization utilization by direction, clips occupied intervals to the observation horizon, and reconstructs queue wait from configured injection times or the previous hop's arrival. Completed-packet latency statistics and successive-packet delay variation exclude pending/dropped packets; individual packet timelines retain those terminal or incomplete states. Browser-derived tables and CSV exports are inspection aids, while the Rust result and Python verification remain the numerical authority.

## Packet network model

`op: network` accepts nodes with `id`, `type`, `x` and `y`; types are router/satellite/base/ue/switch/host. Links have `id,a,b,rateMbps,delayMs,loss,enabled`; flows have `id,source,target,packets,bytes,startMs,intervalMs`. `durationMs` is an observation horizon, not an instruction to discard unfinished packets. Limits are 64 nodes, 128 links, 16 flows and 512 total planned packets.

Routes minimize configured propagation delay plus serialization time for each flow's packet size. Full-duplex FIFO queues reserve a separate serialization timeline in each direction. Serialization delay is bytes·8/(rateMbps·1000) milliseconds. Seeded independent Bernoulli loss is evaluated per traversed link. A priority queue processes injections and arrivals in simulated-time order. This is an abstract finite packet model; it does not simulate a real 5G stack, electromagnetic propagation or physical equipment.

Events are `{tMs,kind,packet,flow,from,to,link,reason?}`. `kind` is send/arrive/drop/delivered. A packet ID is `flowID:index`, with a zero-based index. Send time means actual FIFO transmission start. Arrival includes serialization and propagation. Loss creates a drop at the corresponding arrival time; missing routes drop at injection time.

Per-flow `sent` is the requested packet count and `injected` is the number of birth events inside the horizon. `pending` (also reported as `late`) is requested minus delivered minus dropped, including later injections. Average latency is measured only for delivered packets; throughput divides delivered payload bits by the observation duration. Events outside the horizon are absent without pretending unfinished packets were delivered or dropped.

## Topology and digital events

`op: topology` consumes the circuit component shape, reconstructs a fixed-width legacy connection record and reports reference connectivity. Its topology check is structural; analysis-specific DC capacitor handling remains in the C++ solver.

`op: digital` accepts boolean `inputs`, optional `patterns: {inputName: "binary cycle"}`, `gates: [{id,type,inputs,initial?}]`, `ticks`, `clockPeriodTicks` and `tickS` (default 0.001). AND/NAND/OR/NOR/XOR/NOT/BUFFER/DFF/JKFF are supported. `clock` is reserved. All D/JK registers sample the same settled prior state on a global rising edge, then combinational gates settle again. JK input order is J/K, with hold/reset/set/toggle for 00/01/10/11. Cyclic source strings are sampled before each tick's clock edge. Combinational cycles and unknown wires fail explicitly; ideal feedback through a register is supported. The structured editor provides source patterns, gate types, pin reconnection and initial Q values, with shift-register, parity-latch and synchronous JK-counter templates. Actual trace rows contain `tick`, seconds `t` and boolean `values`; transition events contain wire, old/new state, time and cause. Click the analyzer to inspect a captured tick. Limits are 64 sources, 128 gates, 4096 ticks and 32768 wire/tick cells. The graphical editor adds smaller admission limits for manual additions, while its analyzer shows up to 16 wires and the complete trace/events remain in Data/CSV. No propagation delays, metastability or setup/hold physics are simulated.

## Browser ABI and compilation

The C++ Emscripten ES module `solver.mjs` exports an async default module factory. After initialization, `module.ccall('ocv_run','string',['string'],[json])` returns a copied JSON string. Its underlying C result buffer remains valid until the next call; callers must not free it.

The Rust `communications.wasm` exports `memory`, `ocv_alloc(length)`, `ocv_run(pointer)` and `ocv_dealloc(pointer,length)`. Allocate UTF-8 length plus one, write a null terminator, call `ocv_run`, copy its null-terminated result, then free the input with exactly its original allocation size. The result belongs to the module and stays valid until the next call. Both engines should run in a cancellable Worker; cancellation terminates the Worker rather than claiming a running numerical call was interrupted internally.

The Dockerfile has independent `native-runtime` and `wasm-artifacts` targets. Native runtime executables are `/opt/ocv/ocv-circuit` and `/opt/ocv/ocv-communications`. The runtime container is idle outside controlled, bounded executions. Builds use the original C++ and Rust sources for both browser and native targets. No dormant desktop program or frozen research source is imported.

Ordinary `pnpm build` uses the distributed browser engines and does not install native compilers. To rebuild both native and browser engines explicitly, run `node scripts/build-signals-engines.mjs` from a standard checkout with Docker available. The script builds native and Wasm targets sequentially through a bounded 3 GiB BuildKit container, checks admission against every running container's cap, rejects uncapped foreign containers and stops its builder afterward. Stop optional services first if the configured memory budget would be exceeded.

Compiler output uses `OCV_DEPS_ROOT/tmp` when that local optimization is configured, otherwise the operating system's external temporary directory. Application startup has no dependency on this path. Local Windows storage protection invokes the existing confirmation script before any pull/build; other hosts use their standard Docker installation. `OCV_SIGNALS_BUILD_BUDGET_MIB`, `OCV_SIGNALS_BUILD_RESERVE_MIB` and `OCV_SIGNALS_BUILDER` allow explicit deployment-specific build settings. The defaults are a 6144 MiB capped-container budget, a 1536 MiB Docker host reserve and builder `ocv-after-builder`.

`node scripts/signals-artifacts.mjs --check` verifies artifact and original-source hashes. `NOTICE.txt` accompanies the browser binaries and reproduces the necessary linked runtime licenses; it is included in the artifact manifest.

Reference interfaces: [Emscripten build documentation](https://emscripten.org/docs/compiling/Building-Projects.html) and [Rust wasm32-unknown-unknown target](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html). These are toolchain references; the numerical implementations here are original project source.
