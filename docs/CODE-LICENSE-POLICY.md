# 代码来源与许可处理

2026-10-03 用户要求：媒体采用统一声明，不逐张标注；第三方代码只保留许可证要求及来源追溯所需的信息，不因为安装或运行某个软件就给它另写网站声明。

## 处理范围

- 直接复制或改编的第三方源码，记录实际原始链接、版本或 commit、文件位置、许可及修改情况，保留许可证要求的版权和归属信息。不能把未知许可的公开代码视为可随意复制。
- 实际打包或随发布产物分发的库，包括符合条件的间接依赖，按对应版本的许可证保留 LICENSE、NOTICE、版权注释等必要内容。MIT 库同样可能有保留声明的义务，包大小不是判断依据。
- 单纯阅读文档、借鉴表现思路，且没有复制受保护的实现或素材，不为了凑署名清单而新增声明。现有调研记录继续保留，参考与实际使用区分。
- Docker Desktop、WSL、操作系统及仅供开发者独立安装运行的工具，不因本项目使用它们就加入网页第三方代码声明。安装工具仍适用其自身条款；若以后实际再分发镜像、二进制或工具代码，应另按该交付内容的许可证处理。
- 既有许可原文和历史来源记录保留，不通过本次维护改写或删除；后续发布清单按实际交付范围核对，不机械列出整个技术栈。

Three.js 按 MIT 保留声明；GSAP/ScrollTrigger 使用自己的标准许可证，不改标 MIT。DOMPurify 按已有记录选用 Apache-2.0；mathjs 保留其 LICENSE 和 NOTICE。其他已记录库继续遵守各自许可。现有 Astro 构建在压缩后给 JS chunk 附加归属文本，不借本次媒体声明去掉这些必要信息。

本次只添加统一媒体声明和代码声明阅读入口，不构成第九阶段授权，也不把已有记录当作全部依赖均已核对的证明。发布前仍需核对直接及间接依赖、实际复制片段、Next/Angular/服务器与容器交付中的许可证义务和完整构建产物；不得宣称完整发布许可审计已通过。

## 媒体声明的最新覆盖

`MEDIA_NOTICE.md` 是统一媒体声明的唯一正文来源，`/legal/` 在构建时读取同一文件。用户明确要求不做逐项媒体来源表，不将寻找授权作为本次维护前置条件；网站当前及后续媒体并不因此被标记为已获授权。此前历史报告中“素材许可待核对”的事实不删改，但后续应遵从此项用户选择，不以补逐图来源或取得全部授权为自动阻塞条件。维护者依法承担自身行为的相应责任。

代码许可审计与媒体说明仍分开处理。仓库尚未设置自有代码的最终 LICENSE 时，声明不冒称已经采用 MIT；以后设置 MIT，也不覆盖第三方媒体或第三方代码的独立许可。公开发布前应确保仓库 Issue 或维护者公开联系渠道至少有一项实际可用。
