所有真正依赖在 F:\OCVdeps；包括 Windows node_modules 联接的目标、生成的 Prisma 客户端、镜像内各语言包和编译工具。运行数据在 F: Docker VHDX 的命名卷，不因这些离谱目录而写回 E:/C:。

SQL 归属：ocv_core（阶段一原始 SQL），ocv_prisma（Prisma），ocv_typeorm（TypeORM），ocv_jpa（Hibernate），ocv_unused（永远空的账户遗迹）。MySQL ocv_eloquent_school_student 属于 Eloquent；Mongo school_student_annex / warehouse_logs 属于 Nest Mongoose。

真实收据内部 UUID 一路保留；显示 requestId 每跳都换。Laravel 的返回路径是 Nest 终止窗口，绝不回到链条起点。Rabbit 的 body、Kafka 的 payload、Redis Pub/Sub 的 data 不统一；_internalId 统一。

Windows 的自定义 Prisma 客户端位于 gateway 的 F: 依赖联接目标下。由于物理路径不是名为 node_modules 的目录，link-generated-client.cjs 为它补一个指向已安装 runtime-utils 的 F: 联接；这是模块查找修复，不复制依赖到 E:。Linux 容器用正常 node_modules 路径。
